# Castle Defense (Slotsforsvar) – project notes for Claude Code

Medieval 3D tower defense game for the browser (three.js r128). Built as a hobby project, the goal is fun.
**The user is Danish but prefers replies in English.** All in-game text is English – write it as natural, native English, never a literal translation from Danish. The on-screen title is "Castle Defense"; the repo/package name stays `slotsforsvar`.

## Workflow
The user works in one session per task. Commit when a task is done, and add anything a future session needs to know (new rules, gotchas) to this file or `docs/GAME_DESIGN.md` – a new session only knows what is written down here.
**Every change gets a `CHANGELOG.md` entry** in the same commit: add a bullet under today's date (create the date heading at the top if missing, newest first). Write it for a player, in plain English – what changed, not how the code works. Small tweaks still count; pure notes/docs edits can share one "Project housekeeping" bullet.

## Run
- `npm install` then `npm run dev` → http://localhost:5173 (static server, no bundler).
- `npm run check` → parses all js files in the order index.html loads them (no browser needed).
- `npm run sim` → headless balance simulator, see "Balance simulator" below.
- **Live online:** https://lykhan28.github.io/slotsforsvar/ via GitHub Pages (repo `github.com/Lykhan28/slotsforsvar`, branch `main`, root folder). Friends play there. `git push` updates the site in about a minute, so only push when the game works; ask the user before pushing.
- three.js r128 and its post-processing scripts (EffectComposer, RenderPass, ShaderPass, MaskPass, UnrealBloomPass, CopyShader, LuminosityHighPassShader) are vendored in `vendor/three/` (unchanged copies of the official r128 files, MIT licence alongside). No CDN or internet needed. Don't upgrade three.js casually – the game targets r128 (classic `examples/js` globals, removed in later versions).

## Architecture
Plain classic `<script>` files, **no modules**: they share one global scope, and **load order matters** (see index.html). All code was originally one 113 KB script; the split follows its section markers and is byte-identical to the original.

## Gotchas learned the hard way
- **Function declarations are NOT hoisted across script files.** Top-level code in a file may only call functions defined in earlier files (or itself). This caused a black screen (`chibi is not defined`, then follow-up `rng` errors) when scenery loaded before towers. Functions called later at runtime (from `update`/`sync`/event handlers) are fine.
- **Layers:** most scenery/effects are on three.js layer 1 (`L1()`), the camera must have `cam.layers.enableAll()` or the ground vanishes.
- **`bake(root)`** merges non-animated meshes per material. Anything animated must have `userData.keep = true` and be baked separately. Towers/enemies are baked after construction.
- **Enemy templates** are built once (`tpl[type+v]`, goblins have two looks v=0/1) and cloned with `clone(true)`; animated joints are found by name (`rig[name]`, e.g. `H0/K0` hip/knee, `S/E` shoulder/elbow, `TO` torso, `HD` head, `R0/R1` goblin ears, `T0..` tails, `RD/SP` wolf rider and spear, `JW` jaw, `CP/PL` knight cape and plume, `NK`, `W0/WE0/WH0` dragon wings, `SH` the Shieldbearer's shield, `ST` the Shaman's staff with its glow `GL`, `B0..B4` the bats of a bat swarm with wings `WL0/WR0`…, `BM` the Sapper's bomb with its spark `GL`, `JW` and the basket goblins `G0/G1` of the Troll, `HM` the Ghost's hem and `GL` its glow, `FL` the Fire Imp's flame crest, `WI0/WI1` its wings and `T0/T1` its tail, `CP` the Goblin King's cape, `RM` the Siege Ram's log, `WH0..3` its wheels and `H0..H3/K0..K3` its two pushers' legs, `ST`/`GL`/`OR`/`HM` the Necromancer's staff, flame, orbiting wisps and hem, `JW` the Skeleton's jaw). js/09-game.js, js/13-ending.js (army) and `animEnemy` all drive these names, so keep them (and the pivots' positions) when reshaping an enemy.
- **Enemies are code-built from smooth shapes** (capsules, lathed armour, rounded boxes, extruded blades/shields, flat wing membranes), not downloaded models: free CC0 packs (Quaternius, KayKit) were checked and are either lower-detail or miss the wolf and dragon. Parts are merged per pivot by **`bakeE`**, which joins every part sharing a texture set into one mesh with the colour in vertex colours (materials in `BKM`) – without it an army of 20 cost ~900 draw calls and the frame time doubled. Use the low-poly `eTor`/`eSp`/`eCnD` helpers rather than `part(..,'tor'..)` (640 triangles a ring). An enemy is ~14k triangles, ~30 draw calls; `ESG` lowers segment counts on phones. The army outside the wall casts no real shadows.
- **Never swap enemy materials for hit feedback.** An earlier white-flash did that, also hit the blob shadow (square artefacts) and bloomed. Use `hf()` / `fxStatus()` instead.
- **Name clashes:** terrain noise is `nz`, audio noise is `nzs`. Top-level `const` names are global across files – check for duplicates (`npm run check` catches syntax, not all clashes).
- **Health bar sprites** must be centred at the same point (don't offset in world x), or they drift when the camera rotates.
- Audio only starts after the first user gesture (`auInit`).
- **Layout / HUD (css/style.css):** body is `100dvh` with no page scroll. On wide screens `#wrap` (the 3D view) fills the whole window and the HUD floats over it as frosted-glass panels: `#top` (title + gold/lives/wave pills), `#side` (minimap, camera/sound buttons, `#help` popover), and `#panel` at the bottom (`#ip` inspector, `#dock`/`#towers` tower dock, `#act` wave controls). At ≤700 px wide (phones upright) `#panel` becomes a normal block *below* `#wrap` instead. The dock switches to 4 columns via a **container query** on `#dock` – don't put `container-type` on the element that should shrink-wrap its content (inline-size containment makes it collapse to zero width). Keep new HUD elements from pushing the page taller than the window.
- **Camera framing:** `resize()` in js/02-renderer.js reads `#wrap`'s size (window resize + ResizeObserver). Narrower than 4:3 widens `cam.fov` so the board stays visible. When `#panel` is `position:absolute` (overlaying the view) it uses `cam.setViewOffset` to render the lower part of a taller frustum, which lifts the board above the bottom HUD; `cam.aspect` is then the *full* frustum's aspect (`w/(h+d)`). Raycasting in js/12-input.js works unchanged because it uses the camera's projection.
- **Colour grade:** the overall look (saturation, warm highlights/cool shadows, vignette) lives in the `GRADE` shader in js/02-renderer.js, plus exposure, sky gradient, fog and lights there. Base exposure and sun strength are `EXPO`/`SUN0` – js/13-ending.js dims the scene from them and resets to them, so never hard-code those numbers. Do contrast in the grade *after* the gamma `pow` – contrast around 0.5 in linear space crushes the shadows to black. The game was toned down from a very saturated look on purpose – keep new colours earthy and let emissives (fire, magic) be the bright accents. Without the post-processing scripts in `vendor/three/` the grade pass is skipped.
- **Damage types:** towers have `dt` (`phys`/`magic`/`fire`/`light`, labels in `DTY`) and optionally `pr` (pierces armour, Ballista) in `T`; enemies have `rs` in `E` (every type needs an `rs` object, even `{}`). Every damage path goes through `dmul(e,k)` in js/09-game.js (bullets, catapult splash, poison per second, each lightning jump in `zap`) – a new tower or damage source must too. `hf()` colours the damage number from it (grey resisted, pale gold pierced). The inspector DPS is before resistances. Reference layouts for the armour balance: `scripts/layouts/level1-physical.json`, `level1-mixed.json`, `level4-mixed.json`.
- **Inspector numbers** come from `tstat()` in js/10-ui.js (built on `stat()` from js/09-game.js): DPS counts every target a shot hits (arrows × level, whole lightning chain with −8% per jump); Alchemist DPS is poison per second on each enemy. If you change tower mechanics, update `tstat()` and the chips in `infoHTML()` too. The next-wave preview uses `waveMix(w)` (the types of `waveQ(w)`) and `waveName(w)` in js/09-game.js; `startWave()` queues `waveQ(w)`.
- **Pause and speed:** `g.pause` (not saved; `reset()` clears it) and `g.spd` (saved). The loop in js/16-main.js runs `update(dt)` `g.spd` times a frame (never one big step – keeps cooldowns/collisions stable) and calls `sync(gd,dt)` with the animation clock `gd = dt×spd`, or 0 when paused; the second arg (real time) is only for things that must move while paused (a tower's build pop-in). Anything in `sync()` that spawns or flickers randomly must check `dt>0`, or it piles up while frozen. During the menu and the end sequence `sync` gets real `dt`. `setPause()`/`setSpd()` live in js/10-ui.js; `ui()` shows `#pov` (the overlay lets clicks through except its box) and calls `auPause()` when the state flips. Music tempo comes from `msd()` in js/11-audio.js.
- **Break / early call / auto-start:** in js/09-game.js, `g.brk` counts game time in the break (from wave 1 on, reset by `startWave()` and at wave end), `BRK`=25, `brkLeft()`, `earlyBonus()` and `callEarly()` (adds the bonus, then `startWave()`). The button and Space use `callEarly()`; `startWave()` itself never pays a bonus, so the sim's default runs are unchanged (`--early` switches it to `callEarly`). Auto-start is `autoW` (a `let` in js/09-game.js, set from `OPT.auto` in js/14-menu.js – gameplay settings live in localStorage `sfopt`, separate from `GFX`) and is checked inside `update()`, so it respects pause and speed. `g.brk` is not saved, so a reload restarts the break.
- **Road coverage overlay:** `covM` in js/06-scenery.js is one InstancedMesh with a square per on-board road cell (`RC`); hidden cells get a zero-scale matrix, colours via `setColorAt`, `frustumCulled=false` (an InstancedMesh is culled by the geometry's own bounds otherwise). `covUpd()` rebuilds it only when its key changes and is called from `ui()`, `selRng()` and `hover()`; `COV.pv` is the tower being placed (set by `hover()`, cleared by `selRng()` and on pointer leave), `COV.on` the C-key map, `COVC` its colours (the legend `#covl` is built from them). A cell counts as covered when its centre is within the tower's range.
- **Undo / sell:** a tower placed while `!g.run` gets `t.bw = g.wave` (in `tap()`); `canUndo(t)` (`!g.run && t.bw===g.wave`) makes `sellVal()` the full `t.inv` instead of 60%, and `sellTw()` in js/10-ui.js is the one sell path (button, S, Ctrl+Z/Z via `undo()`). The flag is saved as the 7th tower element, so a reload keeps it. The sim's `sell` step follows the same rule.
- **Upgrade branches:** `BRN` in js/01-config.js (two per tower type, numbers in each entry, field meanings in the comment above it); a tower's pick is `t.br` (0/1, only meaningful at level 3), `brn(t)` in js/09-game.js gives the entry or null. `stat()` applies `dm`/`fm`/`rg`; `dmul(e,k,b)` takes the branch (Crossbow `pr`, Fire Pots' burn passes `FIRE` = `{dt:'fire'}`) – bullets carry `b.br`, and `hf()` gets it too for the number colour. Ground zones (Fire Pots' fire, Time Warden field) are `g.zn`, added by `addZone()` and run by `zones(dt)` at the top of `update()`'s enemy step, which also sets every enemy's time factor `e.tf` (1 outside a field; movement and ability timers use it – `spawn()` sets `tf:1` so enemies spawned mid-loop aren't NaN). Their looks are `zoneFx`/`zoneEnd`/`zoneAnim` in js/07-enemies.js (stubbed in the sim). The picker is built in `infoHTML()` (`.brs`/`.brc`, `brPick(t)`, `brLine()`), clicks go through the `#info` delegation to `upTw(t,br)` in js/10-ui.js (the one upgrade path: button, U, B/N); a level-3 tower without a branch (old save) picks for free. `buildTower()` reads the branch as `b` (-1 none) and changes the model; `chibi(...,bow)` takes 2 = longbow, 3 = crossbow. `tstat(k,l,bf,br)` and the chips know the branches. In the sim, `up c,r NAME` picks a branch by the start of its name; `up` without one gives the old plain level 3 (not possible in the game – the sim runs stay byte-identical that way, handy for comparisons). All nine tower types have branches (the Barracks' are Knights' Hall/Warband: `shp`/`arm`/`sn`/`rsf`, read through `solHp`/`solArm`/`solN`/`solRs` in js/09-game.js; `soldiers()` adds a Warband's fourth soldier, `post()` spaces the posts by `t.sol.length`). Part 2's mechanics, all in js/09-game.js: `big(e,b)` (Giant Slayer), `skewer(e,b)` (called from the bullet hit), `bounty(e)` (added to the kill gold in the death loop), `plague(e)` (death loop, `e.pg` = spread radius; draws through `plagueFx` in js/07-enemies.js, stubbed in the sim), Acid is `e.ac` (timer) read by `dmul()`, Royal Bank interest at the end of a wave after the Treasury income. Banners: `buffs()` (js/07-enemies.js) sets `t.hs` (War Drums haste, divides the reload in `stat()`) and `t.bls` (Blessed Standard); `tbr(t)` is the tower's branch plus `hr:1` when blessed – shots and `dmul()` use `tbr(t)`, the look (`mkBullet`) uses `brn(t)`, so never compare a shot's `b.br` to a `BRN` entry by identity. Every damage path passes the shot's branch to `dmul()`.
- **Hero** (`g.hero`, made by `heroInit()` in `reset()`): all logic in js/09-game.js under "Hero" – `HERO` numbers, `HAB` abilities (spells 0–2 and his Divine Smite 3; see Spells below), `hst(h)` stats per level, `heroHome()` (on-board road cell nearest the gate; `onB(c,r)` = on-board road cell), `heroGo()`, `heroXp(e)` (death loop), `heroUpd(dt)` (in `update()` after `soldiers()`, ), `heroCast(i,x,y)`. He blocks through the same `e.bk`/`held()` as soldiers (his object has `hp`/`e`/`x`/`y`), so `HERO.rg` must stay below `BAR.rg+6`. `pushBack(e,m)` is shared by `banish()` and Lance Charge. Looks: `heroTpl()`/`heroSync()`/`heroFx()`/`heroLvl()`/`heroMark()` in js/07-enemies.js (horse pivots `BD`, `L0..L3`, `TL`; rider `RD` is a scaled chibi kept as its own bake; the sword pivot `SW` is scaled ×1.7; `SL`/`SL2` are the slash arcs (per-hero material clone); the reach ring `h.rg` and target ring `h.tg` live in the scene, not the model, and `reset()` removes them; `heroHit()` (sparks on each hit) is stubbed in the sim – **never bake an already baked group again: `bakeE` re-merging baked meshes loses the vertex colours and everything turns white**). UI: `#hab` (built in js/10-ui.js, `habUI()` refreshed from `ui()`, `heroHTML()`, `cast(i)`); `body.wave` (set in `ui()` while `g.run`) swaps `#towers` for `#hab`. Waves lock building (`tap()` shows the `offT` message) and selling (`sellTw()`, button disabled); keys 1–4 cast during waves (aimed spells via `g.aim`). Saved as `hero:[lv,xp,x,y]` in the run. The sim casts by `heroAI()` in scripts/sim.mjs; `heroFx`/`heroLvl` are stubbed.
- **Achievements:** the game logic only calls `ach(ev,data)` (stubbed in the sim, so new calls need nothing there); everything else lives in js/15-achievements.js. A new achievement needs an `ACH` entry (with `pr()` if it has a count to show) and a check in `ach()`, `achTick()` or `achScan()`. Names in that file are global like everywhere: `ST` and `TQ` were taken (texture quality), hence `AST`/`TSQ`.
- **Royal Armoury / perks:** `PERKS`, `PK` (ranks owned), `pk(id)`/`pkv(id)` (ranks × value) in js/09-game.js; the menu page `mArm()` and loading/saving `sfperk` in js/14-menu.js (stars = `starsAll()` − `starsSpent()`). Effects: tower damage in `stat()` via `PKD` (tower type → perk), `solHp()`, `upCost()`, starting gold and lives in `reset()`, the life cap `maxL()` (replaced the old `MAXL` const; star thresholds `STAR(d)` include it), `hst()`, spell cooldowns in `heroCast()`. `PK` is empty in the sim unless `--perks id:rank,…` / `--perks all`, so reference runs are unaffected. A new perk needs a `PERKS` entry and its effect hooked into the game logic (and `pkTxt()` if its value isn't a +%).
- **Repair gate:** `maxL()`/`REP`/`repCost()`/`repair()` in js/09-game.js (buys a life, `g.rep` counts repairs and is saved as `rep` in the run), `repFx()` in js/07-enemies.js (stubbed in the sim), the `#rep` button inside the lives pill (#top has `pointer-events:none`, the button turns them back on) refreshed in `ui()`, key R. The sim has a `repair` step.
- **Spells** (js/09-game.js, after the hero): `heroCast(i,x,y)` casts them (only while `g.run`, cooldowns in `g.scd`, ticked by `spells(dt)`, which runs in `update()` after `zones()`); numbers in `SPN` (don't call anything `SPL` – that's the sphere geometry in js/04-materials.js), damage scales with `gob()`. Rain of Arrows is an entry in `g.sp` that drops `SPN.vol` volleys; Boiling Oil hits `gateTiles()` (the hero's home cell and the next two road cells, BFS) and adds fire zones with `sl` (they slow); Reinforcements are squads in `g.rf` – Barracks-shaped objects with no tower (`tmp` = seconds left, `n` = soldiers, no respawn) that `soldiers()` runs alongside the Barracks (`g.tw.concat(g.rf)`) and `solSync()` draws; `barGone()` + `squadEnd()` when they leave. Aiming: `g.aim` (spell index or null, not saved) – `cast(i)` in js/10-ui.js sets it, `tap()` casts at `ptX()/ptY()` (the exact point under the pointer from `cellAt()`'s `pt`), `hover()` draws its ring, right-click (`unsel()`) and Esc cancel, the wave end clears it. Looks and sounds: `spellFx(i,p)`/`spellAnim(dt)`/`squadEnd(t)` in js/07-enemies.js (falling arrows and oil streams in `SPA`; stubbed in the sim), sounds `rain`/`oil`/`reinf` in js/11-audio.js. **`classList.toggle(name, x)` needs a real boolean** – `undefined` toggles instead of clearing (that made idle spell tiles flicker to "used")..
- **Level mechanics:** a level's own rule is `mc` in `LEVELS` (numbers, picker name/icon/line in `MECH`, js/01-config.js; the picker shows `.lm` under the description). Darkwood `fog`: `FOG` cells (the ring along the wall) → `fogM(c,r)` multiplies the range in `stat()` (so `stat()`/`tstat()` need the tower's `c,r` – `tstat(k,l,bf,br,c,r)`; the placing ring in `hover()` applies it too). Mirefen `bog`: `LV.bg` → `BOGC`, `bogM(e)` in `update()`'s movement. Each level's per-frame logic runs from `mech(dt)` (`MECHF`, called in `update()` after `zones()`); its looks from `mechAnim(dt)` in js/07-enemies.js (from `sync()`); one-off visual hooks (`burnFx`, `ruinFx`, `graveFx`, `eruptFx`, `darkFx`, …) are stubbed in scripts/sim.mjs, and the first time each mechanic fires it shows an event banner via `evMsg(icon,title,text)` (js/10-ui.js, `#evt`, flags in `MSEEN`). Emberwood `fire`: `g.fire` cells run by `fires(dt)`, `burnAt(c,r)` is part of `free()` (js/12-input.js), so nothing builds there; looks `burnFx`/`burnEnd`/`burnAnim` in js/07-enemies.js (stubbed in the sim), saved as `fire:[[c,r,secondsLeft]]` (optional field, no `v` bump). Ashfall `ruin`: `LV.ru` (cells `RUC`, shortcut road `SC` with `rem`); `ruinOpen(on,now)` moves the cells between `blk` and `road` (so the hero, Barracks, minimap and coverage map – `RC` includes `RUC` – follow) and switches enemies; `spawn()` sends every other new enemy on foot down `SC` (`ruPick()`); `reset()` closes it, `loadRun()` reopens it for a run past `LV.ru.w` (nothing new saved). The ruins on those cells are the unbaked pivots in `RUW` (the blocked-cells loop skips `RUC`). Barrow Moor `grave`: `LV.gv` road cells → `GVP` (road + segment, throws if a grave isn't on a road), skeletons placed like `raise()` does. Badlands `lava`: every blocked cell is a vent (`VENT`), stuns towers via `t.stun`. Dread Wastes `dark`: `g.dk`/`g.dkc`, `darkM(t)` in `stat()` (needs `t.c`; banners never shrink, which is what keeps `litAt()` → `stat(banner)` from looping); `mechAnim` dims `R.toneMappingExposure`/`sun` from `EXPO`/`SUN0` only while `!g.over`. On levels without a mechanic `fogM`/`bogM`/`darkM` are exactly 1 and `mech()` does nothing, keeping the sim reference runs byte-identical (levels 1 checked). Static looks (fog haze `fogs`, bog pools `MUD`, rubble `RUB`, graves and their glows `GVG`, lava light circles `LMPM`) are in js/06-scenery.js.
- **Barracks** (`T.barracks`, flag `bar`): all logic is in js/09-game.js under "Barracks" – `BAR` numbers, `nearRoad(c,r)` (placement rule, checked in `tap()`/`hover()` and the sim), `barInit(t)` (rally point `t.rp` and soldiers `t.sol`, called from `addTw()` and the sim), `setRally()`, `barGone(t)` (sell/undo – must release held enemies, or they stay stuck), `soldiers(dt)` (runs in `update()` right after `zones()`) and `held(e)`: an enemy with `e.bk` (the soldier blocking it) that is `held()` gets `m=0` in the movement step. A soldier is a plain object `{i,x,y,hp,max,cd,rs,e,dir,mv,sw,hit}`; its model is made lazily by `solSync(t,dt)` in js/07-enemies.js (from `sync()`, so the sim never builds one) into the group `t.sg`, which `reset()`/`sellTw()` remove. Soldiers are `chibi(...,4,shieldColour)` scaled ×2.3 (sword pivot `SW`), one template per level and branch (`STPL[l+'_'+branch]`, `solTpl(l,br)`; the Warband swaps the sword pivot's contents for an axe). The rally flag `RFL` shows for the selected Barracks (`rallyHide()`). A road click with a Barracks selected moves the rally point (in `tap()`, before deselecting). Anything new that moves enemies must leave `e.bk` alone or clear it; anything that makes an enemy untouchable should make soldiers let go (they check `e.out`). Soldiers skip bosses (`o.bs`) entirely – only the hero can block a boss. The sim has `barracks c,r` and `rally c,r C,R` steps; `solDie` is stubbed.
- **Targeting modes:** `TGM`/`TGK`, `tmode(t)` (`t.tm`, else `T[k].tm` – Ballista `'strong'` – else `'first'`) and `tscore(t,e,m)` in js/09-game.js; `update()` and `volley()` both rank by `tscore`. Keep the defaults scoring exactly as before (plain `prog(e)` / `e.hp`) – the sim reference runs stay byte-identical that way. Picker is built in `infoHTML()` (`.tgm`, click handled by delegation on `#info`), `setTm()` in js/10-ui.js. Saved as the 6th tower element (`null` = default), so old v1 saves still load. The sim has a `target c,r MODE` build step.
- **Main menu pauses the game:** while `MENU.open`, the loop skips `update()` (only `sync()` runs) and a capture-phase keydown listener in js/14-menu.js swallows game hotkeys. Quit sets `MENU.quit`, which stops the render loop entirely; `menuBack()` restarts it. Browsers only let `window.close()` close tabs a script opened, so Quit normally ends on the "Thanks for playing" page.
- **Difficulty:** `DIFS`/`DFN`/`DF` in js/01-config.js, picked at load like the level (`?diff=easy|normal|hard`, else localStorage `sfdif`; a player with old progress defaults to Easy, a new one to Normal). It multiplies enemy health in `spawn()` and `gob()` (`LV.hp*DF.hp`), starting gold in `reset()`, and sets `g.lives`/`MAXL` (`DF.li`). Easy must stay 1/1/20 – it is the original game and what the sim reference runs measure. Saved runs use `runK(i,di)` (`sfrun<i>` for Easy, plus `n`/`h`). The sim takes `--diff` (default easy).
- **Saved runs:** `saveRun()` runs at the end of every `ui()` call and writes the run (gold, lives, wave, speed, towers as `[k,c,r,l,inv,tm,new,br,rally]`, and the hero as `[lv,xp,x,y]`) to localStorage `sfrun<LVN>` only when `!g.run` and it changed – so the save is always the state at the start of the next wave, never mid-wave. `g.over` (win or defeat) deletes it, so a refresh can't undo a defeat. A fresh `reset()` state is never written and never deletes the save (Quit calls `reset()` and `menuBack()` calls `loadRun()` again); only `restartLevel()` deletes it on purpose. `loadRun()` runs at load right after `reset()` (js/16-main.js) and rebuilds towers with `addTw()` (js/12-input.js). If you add run state that matters between waves (new resources, tower paths/targeting, spells), add it to the save and bump `v` – old saves with another `v` are ignored.
- **The in-game changelog reads `CHANGELOG.md` over HTTP,** so keep its format (`## YYYY-MM-DD` headings, `- ` bullets, `**bold**`). `.nojekyll` in the repo root makes GitHub Pages serve the .md file as-is – don't delete it.
- **Ambient occlusion (GFX.ao):** `aoDraw()` renders a half-size depth-only prepass of the opaque meshes on layer 3 (`AOL`), re-marked every frame: transparent and alpha-tested materials (glows, water, grass/leaf cards) and meshes smaller than 0.3 world units (`userData.aor`, re-measured every 30 frames) are left out – the enemy army alone has ~850 tiny parts, which made the prepass cost 7 ms. Then a screen-space AO shader, then `AO.pass` in the composer (before bloom) blurs it depth-aware and multiplies the image. Default on unless `LOWQ`. `THREE.ShaderPass` **clones its uniforms**, and a cloned texture loses its render target (black screen) – set texture uniforms on `pass.uniforms` after constructing it.
- **The board is one surface:** there are no road tile meshes on the board any more. Its top face uses a shader (js/06-scenery.js) that blends grass, a dirt shoulder and cobbles from `BMK`, a blurred mask of the road cells (r = road, g = wider shoulder), with edges broken up by noise; colours come from `TH.bd`, `TH.rd` and `TH.gr`. Only the breach/gate cells outside the board still have cobbled slabs (`RDM`). Enemies and towers stand at y=0. When writing GLSL into a JS string here, use `\n` inside quotes, not a real line break (shell heredocs and `node -e` easily turn it into one – prefer the Edit tool).
- **`genTex(S0,fn,ns,D)`:** `fn` is written for a D×D image (256 for the existing textures); a bigger S0 samples it at fractional coordinates, so detail scales without rewriting the pattern.
- **Towers keep their animated handles:** js/09-game.js animates `t.head`/`t.hy`, `t.aimG`, `t.arm`+`t.ball` (catapult), `t.stf`, `t.rcl` (ballista), `t.spin`, `t.flag` and the flames in `t.fl` – a rebuilt tower must set the same ones, at the same heights (bullets start from `t.head`). Towers are ~10–30k triangles and ~19 draw calls each after `bakeE`; `rboxG` uses a single bevel segment and `eSp` a low-poly sphere below 0.03 to keep that down (a packed board of 65 towers still runs, at ~26 ms a frame). The loose stones on tower walls use plain colours – the brick texture on a small rounded box looks like a badge. Flat shapes (banners, pennants, wing membranes) need `matDS` and should face the default camera, or they vanish edge-on.
- **Verify in a browser before claiming something works.** Start the dev server via `.claude/launch.json` (config `dev`, port 5173; if the port is taken by another session's server, use config `dev-alt` on port 5174), read console errors and take a screenshot. Everything is global, so you can inspect or drive the game from the page's JS console (`g`, `T`, `ui()`, `startWave()`), e.g. set `g.sel`/`g.over` to check panels and end screens without playing.

## Levels
- 16 levels in `LEVELS` (js/01-config.js), each with its own theme in `THEMES`: Greenmeadow (field) → Darkwood → Emberwood (burning forest, burnt houses) → Mirefen (marsh) → Ashfall (ruined town) → Barrow Moor (graveyard) → Scorched Badlands (lava) → The Dread Wastes → Harvest Vale (`autumn`) → Saltcliff Cove (`coast`, pirates) → Sunscorch Dunes (`desert`) → Frostpeak Hold (`snow`, mountain fortress) → Crystal Hollow (`crystal`) → Wolfjaw Pass (`pass`, one narrow road) → Stormwatch Heights (`storm`) → The Sundered Realm (`void`, the finale). Later levels get more blocked cells, roads with fewer overlaps, and levels 7, 8, 11, 13, 15 and 16 have two breaches. Winning a level unlocks the next. Levels 9–16 have no level mechanic (`mc`) yet. Nothing counts levels by hand: the picker, unlocks, stars, the end screen's "Next level" and the all-levels achievements all use `LEVELS.length`.
- **The level is chosen once at page load** (`?level=N` in the URL wins, else localStorage `sflv`) and the whole scene is built for it. Switching level reloads the page (`goLevel()`; sessionStorage `sfgo` makes the new page skip the menu). Don't try to swap levels at runtime – everything is top-level `const`s and baked meshes. `?level=N` is handy for testing any level without unlocking it.
- **Breach and castle frames:** the castle and breach scenery are still modelled in their original coordinates (gate on the east wall at z=2.5, breach on the west wall at z=-2.5). They're wrapped in groups turned to face the level's gate/breach; for world positions of those original coordinates use `CW(x,z)` (castle, e.g. ending fires, fireworks, keep) and `BW(x,z,i)` (breach i, e.g. the enemy army), and `toC`/`toB` for the inverse.
- A road is a list of cell waypoints from just outside the wall (the breach side is worked out from it) to just outside the gate; all roads must end at the same gate. Enemies carry their road in `e.R`; `prog()` compares remaining road length so towers pick the right target across roads (it's negative – never start a "best so far" at -1).
- The default camera looks from the south, or from the north when the castle is on the south side (`CAM0`). Scenery is denser on the far side (`ZF`), and trees near the camera's wall are kept back so they don't hide the board.
- Theme colours go through `TH` (sky, fog, lights, ground, grass, rocks, smoke, grade saturation/tint). Barren themes set `gt:'dirt'` to swap the grass texture for bare earth; `gt:'snow'`/`'sand'` use `TX.snow`/`TX.sand` (made in js/06-scenery.js next to `TX.dirt`). Rock colour `rc` matters – the default light rock glows against dark ground. Theme flags: `sea` drops the far side into the sea (`seaK()` in `gh()`; `okSpot()`/`outside()` keep props and grass out of the water, so the sea must stay on the far side – keep the coast's castle and breaches off it), `storm` adds rain (`RAIN`) and lightning with thunder (`STM`), both run in `moteAnim()`. Falling leaves and snow are `mo` particles of kind `ash`. Each theme's props live in one `if(LV.th==…)` block in js/06-scenery.js (the new lands' blocks follow the marsh one; helpers `ship`, `pillar`, `haystack`, `pumpkin`, `crys`, `windmill`, `palm`), its blocked-cell look in the `for(const k of blk)` loop. Floating things (ships, the void's islands) go in `bobs`. Tree kinds in `TH.tk`: 0 pine, 1 green broadleaf, 2 orange, 3 birch, 4 dead, 5 charred, 6 tall pine in `TH.pine`, 7 burning pine, 8 `TH.leaf` with moss, 9 palm, 10 red autumn, 11 `TH.leaf` without moss.

## Balance simulator
**Check every balance change with it** (tower/enemy numbers, wave mix, gold, health scaling, targeting): run the same layouts before and after and compare. `scripts/sim.mjs` plays all 20 waves of a level with a build order, without a browser, and reports per wave: gold before/after, income, spending, lives, leaks, towers and wave length, plus the final board and VICTORY / DEFEAT on wave N.
- `npm run sim -- --map 3` prints level 3's board with cell coordinates (`#` road, `x` blocked, `.` buildable). `--waves 3` prints its wave table. `--hp X` / `--gold N` try another health multiplier / starting gold without editing `LEVELS`. The report's last column lists the enemies that leaked each wave (by `WC` letter, e.g. `12v` = 12 bat swarms) – the quickest way to see *why* lives were lost.
- `npm run sim -- scripts/layouts/level1-example.json` runs a layout file: `{"level":1,"build":["arrow 8,2","up 8,2","sell 8,2","wave 5", ...]}`. Or give steps on the command line: `npm run sim -- --level 2 --build "arrow 3,3" --build "cannon 5,2"`.
- Build steps run strictly in order as soon as there's enough gold (on Emberwood a step on a burning cell waits, and the sim lets the break run on – up to `BRK` s – until it's out); **building and selling wait for the break** (as in the game), upgrades, `target`, `rally` and `hero c,r` work mid-wave too. A step that can't be afforded blocks the ones after it. `wave N` holds the queue until the break before wave N. Steps on unbuildable cells are skipped with a warning.
- `--keep-going` ignores defeat and plays all 20 waves (lives go negative – shows how badly a layout fails). `--json` gives everything machine-readable, including gold every 5 s of game time (`gold`), for comparing runs in a script.
- **How it works:** it runs the real `js/01-config.js` and `js/09-game.js` in a Node `vm` sandbox, plus `volley`/`zap`/`buffs` cut out of `js/07-enemies.js` and the `const free=` line from `js/12-input.js` by name; everything visual or audio (`snd`, `burst`, `hf`, `buildEnemy`, `mkBullet`, `ui`, …) is stubbed. So balance edits in those files are picked up automatically. If you add a new function that `update()` calls, either add it to the extracted list or stub it in `scripts/sim.mjs` – the sim dies with "X is not defined" otherwise. Building, upgrading and selling are re-implemented there (copies of `addTw()`/`tap()` in js/12-input.js and the up/sell buttons in js/10-ui.js, plus the Barracks' placement and rally rules) – keep them in step if those rules change.
- It steps `update()` at a fixed 1/60 s (`--dt`), and `Math.random` is seeded (it only affects looks), so runs are reproducible. Checked against the real game in the browser: the example layout gave identical gold and lives after all 20 waves.
- Keep a few layouts per level in `scripts/layouts/` as reference runs when tuning.

## Current rules (details in docs/GAME_DESIGN.md)
9 tower types (the Wizard has key `frost` for historical reasons; it now banishes enemies back along the road via `banish()` in js/09-game.js, enemy field `bn` = immunity timer; the 9th is the Barracks, see below), 15 enemy types (goblin `norm`, wolf rider `fast`, Black Knight `tank`, Shieldbearer `guard`, Shaman `shaman`, flying bat swarm `bat`, Sapper `sapper`, Troll `troll`, Ghost `ghost`, Fire Imp `imp`, Skeleton `skel`, and the bosses Dragon `boss`, Goblin King `king`, Siege Ram `ram`, Necromancer `necro`), 20 waves, a boss every 5th wave. **Bosses** are written into the wave tables (see Waves below); boss behaviour keys off `E[type].bs` and lives lost off `lv` (never test `type=='boss'` for gameplay – that's only the Dragon's own visuals in `animEnemy`/`animDying` and the ending army). `bossBar()` in js/10-ui.js (called from `ui()`) draws `#bb`. Goblin King `summon()`/`KING`, Necromancer `raise()`/`NEC` with the corpse list `g.cps` (filled in `update()`'s death loop) – both in js/09-game.js, their effects `kingFx()`/`raiseFx()` in js/07-enemies.js (stubbed in the sim). Per-type look-up tables: a letter in `WC` (js/01-config.js, for the wave tables), and in js/07-enemies.js (`BR`, `HT`, `TXY`, the `stick` heights and the hit/low-health burst colours), the walk speed `k` in `spawn()`, `FOE` in js/10-ui.js and the `die_<type>` sounds – a new enemy type needs an entry in all of them. The Shieldbearer's frontal block is `shBlk()` and the Shaman's pulse `heal()`/`HEAL` (both js/09-game.js); `heal()` draws through `healFx()` in js/07-enemies.js, which the sim stubs. Don't call a new helper `blk` – that's the blocked-cell set.
- **Flyers:** `E[type].fy` = flying height. `spawn()` gives a flyer its straight route from `FPATHS` (same shape as a road, with `rem`, so `prog()`, `banish()` and leaking just work). Towers need `air` in `T` to target it (checked in `update()` and `volley()`); the Catapult splash and the Alchemist cloud skip `fy` enemies. The model itself is built at height (the swarm's `TO` sits at y≈1.05, so the blob shadow stays on the ground), bullets and Storm bolts aim at `e.fy`, and `animDying` drops it to the ground. A future Barracks/blocking tower must ignore flyers.
- **First sighting / Bestiary:** `spawn()` calls `foeSeen(type)` (js/10-ui.js; stubbed in the sim): the first time a type ever spawns it is stored in localStorage `sfseen` (type → [level, wave]) and queued for the card `#foe` (`FC`, `foeNext()`/`foeDone()`), which pauses via `setPause` and restores the player's own pause; `ui()` hides the Paused overlay while the card is up, and a capture-phase keydown listener takes Space/Enter/Esc so Space doesn't also start a wave. Names and descriptions live in `BST` (js/10-ui.js, also the bestiary order), facts come from `foeChips()`. **A new enemy type needs a `BST` entry** or it never gets a card or a bestiary row. Portraits come from `portrait(type)` in js/07-enemies.js: the type's template rendered by the main renderer into a 192² sRGB render target (own lights, `sc.environment`, exposure 1, transparent background), read back and cached as a PNG data URL in `PORT` – sprites without a map (health bars), the ice ring and the blob shadow are hidden. Note: in a hidden browser tab CSS animations don't run, so the card can look invisible in a screenshot – check the DOM or turn animations off for the check.
- **Ghost / Fire Imp:** a Ghost with `e.out` set can't be targeted, hurt by splash/poison/chains, and bullets at it vanish – every new way of hitting enemies must check `out`. Its see-through look uses per-ghost material clones (`gm`, made in `buildEnemy()`, disposed in `animDying()`), the one exception to never touching enemy materials. Towers skip enemies with `dmul(e,k)<=0` (Fire Imp `rs:{fire:1}` vs the Alchemist); `resTxt()` shows a resistance of 1 as "immune to …". Every enemy type also needs an entry in `spawn()`'s gait table `k` – a missing one turns `e.gp` into NaN and the model vanishes. The sim prints each type by a letter (`mixS` in scripts/sim.mjs: v bats, p Sappers, r Trolls, i imps, h ghosts, k Goblin King, m Siege Ram, x Necromancer, z skeletons; the rest by their first letter).
- **Sapper / tower stun:** `sapMove()` in js/09-game.js takes over a Sapper's movement while it is off the road (`e.tw2` target, `e.back` returning to `e.rx/e.ry`); blowing up sets `e.gone` (removed with no gold, like `e.leak` without the life). A tower with `t.stun>0` skips its whole turn in `update()` and is left out of `buffs()`; `sync()` draws the stars. Anything new that a tower does each frame should respect `t.stun`. **Troll:** killed enemies with `spl` are collected in `update()`'s death loop and `trollSplit()` spawns the goblins after the filter (never push into `g.en` while it is being filtered).

## Waves
- **Hand-designed per level:** `WAVES` in js/01-config.js (20 strings per level, attached as `LEVELS[i].wv`), format in the comment above it: `"Name: 6n ~2 14f/.35 4t/1.2@1"` – groups of `<count><letters>[/gap][@road]` (letters cycle, letters in `WC`), `~s` = extra pause. `waveQ(w)` in js/09-game.js parses it into the spawn queue `[{t,type,p}]` and **throws** on a typo (bad group, unknown letter) – run `npm run sim -- --waves N` after editing a table, it parses and prints every wave (count, health in goblin units, gold, spawn time). Health still scales as `30 × 1.2^wave × E.h × LV.hp`.
- Without `@road` enemies alternate roads by their index in the whole wave (as before). A new enemy type needs a `WC` letter to appear in waves.
- **Tuning:** the reference builds are `scripts/layouts/levelN-full.json` (one per level, keep spending gold to the end). After the tuning they won every level, losing 0 / 8 / 12 / 12 / 10 / 13 / 14 / 15 lives; with upgrade branches (they pick Crossbow Nest, Fire Pots, Archmage, Tempest, Giant Slayer, Acid Brew, War Drums, Royal Bank) that dropped to 0 / 0 / 5 / 0 / 0 / 3 / 0 / 0 – the user chose to keep the game easier rather than raise enemy health. With the hero (waiting by the gate) and building locked during waves: 0 / 0 / 3 / 0 / 0 / 3 / 0 / 0. `LV.hp` was used to even out the boards (it is *not* a difficulty ranking any more – Barrow Moor is ×0.8). Levels 9–16 were tuned the same way; their full builds are generated from the board (the cells covering the most road for the same step template – see the note in each file): Easy 0 / 0 / 0 / 0 / 0 / 5 / 0 / 0, Normal 5 / 5 / 10 / 4 / 7 / 12 / 12 / 2 of 15, and on Hard only Harvest Vale is won. Bats are dangerous where the flight line misses the towers – keep bat groups small and spaced out. **Endless mode:** `INF` (a `let` in js/09-game.js, set at load in js/14-menu.js from `?endless=1` / localStorage `sfmode`, only if the level is won on `DF`). Past `MAXW` the wave string comes from `endWave(w)` through `wvS(w)` (seeded, same table format, so `waveQ`/`waveName`/`waveMix` just work; `EWV` numbers), health from `wHP(w)` (identical to the old `30×1.2^w` up to wave 20 – keep it so). Every `g.wave<MAXW` gate must also pass when `INF` (break/auto-start, next-wave preview). The wave end calls `infRec()` instead of winning (highscore `BEST[diff][level]`, localStorage `sfbest`, `g.rec` = new record this run). Saved runs: `runK(i,di,inf)` adds `e`, and `savedRun()` skips the `wave<MAXW` check for endless. `goLevel(i,di,inf)`. The sim has `--endless` (plays up to 100 waves, `--waves N --endless` prints 1–40).
